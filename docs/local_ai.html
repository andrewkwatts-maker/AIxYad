Local AI gateway: how to

Run Qwen3.8-Flash-Next and smaller models on this PC (RTX 3070 Ti 8 GB, 128 GB RAM) and a second PC, drive them from VS Code, Claude Code or a phone, and let a big planner model hand steps to worker agents. Package: Automatica/local_ai. API: local_ai/API.md. VS Code extension: the Automatica-Code repo.

1. How it fits together

ClientsVS Code extension, Claude Code / Qwen Code, the phone page, any OpenAI- or Anthropic-style tool
Gateway python -m local_ai.gateway on 127.0.0.1:8770: token auth, routes by role, queues per model server, runs jobs
This PC's GPU (group gpu0)the big model (dense tensors on the GPU, experts in RAM) or a small model fully on the GPU, one at a time
Second PCa small model, vision or image model on the GTX 970, reached over Tailscale
  • Routes are roles named in the request's model field: planner (big model, thinking on), worker (thinking off, capped output), plus any you add (fast, vision, ...).
  • One model per GPU at a time. The 8 GB card cannot hold the big model's dense tensors and a fast small model together, so backends in one group are swapped. A loaded model serves all of its queued work, including work that arrives meanwhile, before it is unloaded. A swap happens when its queue is empty, or when another model's request has waited longer than swap.max_hold_s; the loaded model then stops taking new work, finishes what is running, and hands over.
  • The network carries whole requests, not layers. Splitting one model's layers across two PCs (llama.cpp RPC) adds a network round trip per layer group per token, has no authentication, and does not speed up answering, only capacity. Over Wi-Fi it would be slower than the 3070 Ti alone. Each PC serves its own models instead.

  • Dense tensors on the GPU tripled answer speed (5 → 15–16 tok/s). The 256k context Unsloth asked for left no VRAM for them.
  • These rows over-filled the card. --fit does nothing when --cpu-moe or -ot is also given ("tensor_buft_overrides already set by user, abort"), so every layer went to the GPU and the driver paged 0.7–1 GB to system RAM. Answers stayed fast because the driver evicts the least-used memory first; long prompts paid for it. The profiles now use --fit alone.
  • Two agents at once share the speed: ~8.7 tok/s each, ~17.5 together, only ~16% more than one. With 512 experts per layer two agents rarely read the same experts, so RAM bandwidth is the limit. Faster RAM is the lever (section 3).
  • An expert cache does not pay on 8 GB: it takes VRAM the context and compute buffers need.
  • VRAM spill makes long prompts erratic (35 vs 120 vs 276 tok/s at 16k, depending on which buffer the driver pushed to system RAM). Fix the spill (section 3) before tuning further.

Context window: choose it when you load

Coding agents need room: Claude Code's own instructions are 15–20k tokens before any of your code. The big model's context is set when it is loaded (VS Code's Start Model Server, the phone page's Load, or POST /gateway/backends/big/start {"vars": {...}}), not baked in:

VariableMeaningDefault
ctxcontext per agent, tokens65536
slotsagents served at once. The cache is one shared pool of ctx × slots tokens, and any one agent may use all of it while the others are idle; ctx is the fair share when all are busy.2
cacheq8_0 (best) or q4_0 (half the memory)q8_0
ubprompt-reading batch (bigger reads long prompts faster but needs VRAM)256

Why big contexts are affordable here: only 12 of the model's 48 layers keep a growing attention cache; the other 36 are DeltaNet layers with a fixed-size state. 1k tokens of context cost about 16 MB at 8-bit, 9 MB at 4-bit, so 128k is ~1.1 GB at 4-bit. That memory comes out of the GPU, so --fit moves some layers' dense tensors to the CPU to make room (a bit slower), or use big-kv-ram: the cache lives in RAM, every dense layer stays on the GPU, and the 12 attention layers read their cache from RAM.

Measured so far (2026-10-10): with --fit doing the placement and a 1,152 MB margin, 2 agents × 32k at 8-bit puts 29 of 49 layers' dense tensors on the GPU and reads a 32k prompt at ~125–140 tok/s. The full context sweep (64k, 128k at 4-bit, 128k with the cache in RAM, 256k for one agent) has not finished cleanly yet: other sessions' builds held the CPU at 50–100% and pushed the model's 27 GB n-gram table out of RAM (answers fell to 1.5 tok/s). Rerun it on a quiet PC: python -m local_ai.bench big-32k big big-128k-q4 big-kv-ram-128k big-256k-1 --deep 32768.

Locking the model in RAM (load: mlock or mmap+mlock) failed on this PC while builds ran: Windows' commit limit (127 GB RAM + a 7 GB page file) was used up. A larger page file on D: raises the limit; the model still needs ~82 GB of real RAM beside everything else.

4. Run the gateway

  1. Machine paths go in %USERPROFILE%\.automatica\local_ai.yaml (merged over the packaged local_ai/local_ai.yaml): 
    defaults:
  binary: C:/Users/Andrew/.unsloth/llama.cpp/build/bin/Release/llama-server.exe
  model: D:/Models/Qwen3.8-Flash-Next-UD-Q3_K_XL/Qwen3.8-Flash-Next-UD-Q3_K_XL-00001-of-00003.gguf
  dll_dirs: [C:/Users/Andrew/.unsloth/studio/unsloth_studio/Lib/site-packages/torch/lib]
  2. Start it from the Automatica folder: python -m local_ai.gateway. The token is created in ~/.automatica/gateway.token; python -m local_ai.gateway --print-token shows it.
  3. The big model loads on the first request (about 70–80 s), or press Load in VS Code or on the phone page.
  4. Any OpenAI- or Anthropic-style client can use it: base URL http://127.0.0.1:8770 (Anthropic) or http://127.0.0.1:8770/v1 (OpenAI), key = the token, model = planner or worker. Unsloth Studio can use it too: Settings → Connections.
  5. To add the fast small model to the GPU group, add to the user file: 
    gateway:
  backends:
    small-gpu: {profile: coder7b-gpu, group: gpu0}
  routes:
    fast: {backend: small-gpu, thinking: false}
    Point worker at small-gpu to have every worker step use it; the scheduler then loads the big model for planning and swaps to the small one for the steps.

5. Planner and worker agents

A job (POST /gateway/jobs, the VS Code panel or the phone page) runs a coding CLI headless:

  1. Plan: Claude Code with read-only tools on the planner route explores the repository and returns a JSON plan of up to 8 steps, each with complete instructions and the files it will edit.
  2. Review (optional): the job waits; edit, remove or approve the steps.
  3. Delegate: each step runs as its own Claude Code process on the worker route, in one git worktree per job (<repo>.agents\<job> beside the repo, branch claude/local-ai/<job>, never pushed by the ecosystem sync). Steps run in parallel when their dependencies are done and their files do not overlap.
  4. Review the result: nothing is committed. The job's last event lists the changed files; open the worktree, check the diff, merge what you want.

Each CLI runs with its own config folder (~/.automatica/cli/claude), so your normal Claude Code sign-in, settings and history are untouched, and gets the gateway address and token only in its environment. Shell commands are off unless the job allows them.

Claude Code is proprietary: each user installs it and accepts Anthropic's terms; pointing your own install at a local server is the documented LLM-gateway setup. Qwen Code (Apache 2.0) is supported by the job runner but was not installed when this was written.

6. VS Code

Build and install the extension from the Automatica-Code repo: build.bat, then code --install-extension automatica-code-0.1.0.vsix. Commands: Automatica: Open Local AI Panel, New Task (uses the editor selection if there is one), Start/Stop Model Server, Set Gateway Token, Copy Phone URL. The status bar shows the model's last answer speed and busy slots. Settings start with automatica..

7. Phone and browser

  1. Install Tailscale on this PC and the phone (free Personal plan) and sign both in to the same account.
  2. Share the gateway inside your tailnet only, with HTTPS: tailscale serve --bg 8770. It stays bound to 127.0.0.1; Tailscale forwards to it, and nothing is opened to the internet.
  3. On the phone open https://<this-pc>.<tailnet>.ts.net/ui?token=<token> once. It sets a cookie and the address becomes plain /ui; bookmark that. The page shows the model servers (load/unload), jobs, plan approval and live agent output, and starts new tasks.

The Automatica-App phone client can use the same gateway API later; the page needs nothing installed.

8. The second PC (GTX 970, 32 GB RAM, Wi-Fi)

Use it for whole requests that would otherwise take the 3070 Ti away from the big model:

Make imagesSD 1.5, or Z-Image-Turbo at Q3/Q4 with CPU offload (tens of seconds per image)stable-diffusion.cpp sd-server (OpenAI-style /v1/images)
  1. On the second PC: install Tailscale, unzip llama.cpp's Vulkan build (CUDA 13 no longer supports the 970's Maxwell chip), copy local_ai/node/start-node.ps1 and run it with a model. It binds to the Tailscale address only and creates an API key file.
  2. Copy the key file to this PC and add the backend: 
    gateway:
  backends:
    lan-small: {url: "http://<second-pc>:11437", model: lan-small, slots: 1,
                api_key_file: ~/.automatica/node.key}
  routes:
    fast: {backend: lan-small, thinking: false}
  3. The gateway checks its health every 15 s and shows it as unreachable when that PC is off or busy.

It is someone else's everyday PC: start the node only when it is free (or schedule it), and keep its context small (16k) so it stays within 4 GB.

9. Benchmark a change

python -m local_ai.bench --list
python -m local_ai.bench fit-32k fit-32k-ub256        # load, measure, unload each in turn

Results append to ~/.automatica/bench/results.jsonl; server logs are in ~/.automatica/bench/logs. Tests: one answer (512-token prompt, 192 tokens), a 4k prompt, 4 agents at once, and a 16k-deep context. Each result records the background CPU load before each test, VRAM requested versus really held (gpu_spill_mib), and where the layers went. Add a profile to the user file (it can extends: another) to try a new flag. Stop the gateway first: only one copy of the model fits in RAM.

10. Troubleshooting

Server runs but the GPU stays idlellama-server --list-devices shows none: the CUDA DLLs are not on PATH (dll_dirs).
Prompt reading very slow at long contextVRAM spill: check gpu_spill_mib, set the sysmem fallback policy, close VRAM users, or use a smaller -ub or context.
Agents time out on the first requestA fresh Claude Code prompt is 15–20k tokens; the first one takes minutes at a few hundred tokens/s. Later ones reuse the prompt cache.
Job fails with "no JSON plan"The planner's reply had no plan; open the job's events to see what it said, and retry with a more specific task.
A backend stays in errorIt failed to start (see ~/.automatica/servers/<profile>.log); press Load to retry after fixing.
